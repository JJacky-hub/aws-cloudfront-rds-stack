# AWS Fault-Tolerant WordPress Infrastructure

A production-ready, scalable, and secure multi-tier web infrastructure deployed on AWS, separating compute, managed database, and edge distribution layers.

---

## 🏗 Architecture Overview

```text
  [ Clients / Browsers ]
            │
            ▼
     [ AWS CloudFront ]   <-- Edge Layer (HTTPS Termination, CDN Caching)
            │
            ▼
        [ AWS EC2 ]        <-- Compute Layer (Nginx 1.24 + PHP 8.3-FPM)
            │
            ▼
        [ AWS RDS ]        <-- Database Layer (MySQL 8.0, Isolated in VPC)
```

### Components:
* **Edge Layer (CDN):** AWS CloudFront handling global HTTPS termination, static content caching, and forwarding dynamic requests.
* **Compute Layer:** AWS EC2 (Ubuntu) running Nginx 1.24 as a reverse proxy and PHP 8.3-FPM over UNIX sockets.
* **Database Layer:** AWS RDS (MySQL) isolated from the public internet, accessible strictly from the EC2 instance via Security Groups.

---

## ⚙️ Key Features & Security Architecture

* **Multi-Tier Network Isolation:** RDS database is placed in a private network context with access restricted to Port `3306` exclusively for the EC2 Security Group.
* **Nginx & FastCGI Socket Optimization:** Configured direct FastCGI socket communication (`/run/php/php8.3-fpm.sock`) with optimized rewrite rules for WordPress permalinks.
* **CDN Method Handling:** CloudFront behaviors configured to support full HTTP methods (`GET`, `HEAD`, `OPTIONS`, `PUT`, `POST`, `PATCH`, `DELETE`) for seamless admin/API interactions.
* **Hardened Permissions:** File permissions enforced using strict owner boundaries (`www-data:www-data`, `755` directories, `644` files).

## 🛠 Engineering Challenges & Troubleshooting

### 1. CloudFront 403 Forbidden on HTTP POST Requests
* **Issue:** Form submissions during WordPress initialization resulted in `403 ERROR: The request could not be satisfied` generated by CloudFront.
* **Root Cause:** Default CloudFront behavior allowed only cached read-only requests (`GET`, `HEAD`).
* **Resolution:** Updated CloudFront **Allowed HTTP Methods** to include full REST verbs (`GET`, `HEAD`, `OPTIONS`, `PUT`, `POST`, `PATCH`, `DELETE`).

### 2. Nginx 404 Not Found & Blank Responses on PHP Execution
* **Issue:** Accessing `/wp-admin/install.php` returned `404 Not Found` or empty HTTP 200 responses.
* **Root Cause:** Mismatch between Nginx FastCGI socket configuration, missing required PHP extension modules (`php-mbstring`, `php-xml`), and missing core distribution files.
* **Resolution:** Installed missing PHP modules, re-linked the exact socket `/run/php/php8.3-fpm.sock`, and re-extracted fresh WordPress core assets into `/var/www/html`.

## 🚀 Quick Deployment Guide

1. **Database:** 
   Provision an AWS RDS MySQL instance. Restrict inbound rule on port `3306` to your EC2 instance Security Group ID.

2. **Compute Setup:** 
   Launch an Ubuntu EC2 instance. Install Nginx and PHP-FPM:
   ```bash
   sudo apt update && sudo apt install nginx php8.3-fpm php-mysql php-xml php-mbstring php-curl php-gd php-zip -y
   ```

3. **Web Server Setup:**
   * Copy `configs/nginx-default.conf` to `/etc/nginx/sites-available/default`.
   * Extract WordPress core into `/var/www/html/`.
   * Apply ownership and permissions: 
     ```bash
     sudo chown -R www-data:www-data /var/www/html
     ```

4. **Database Connection:** 
   Rename `wp-config-sample.php` to `wp-config.php` and set your RDS Endpoint, DB Name, and Credentials.

5. **CDN Provisioning:** 
   Create an AWS CloudFront distribution pointing to the EC2 Public DNS. Ensure **Allowed HTTP Methods** includes `POST/PUT` and enforce HTTPS.
